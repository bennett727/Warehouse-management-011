# 未引用组件整合实施方案

**文档版本**: 1.0  
**编制日期**: 2026-02-13  
**编制人**: 前端架构团队

---

## 1. 方案概述

本方案旨在将当前未被引用的33个组件整合到系统中，通过合理的功能设计和页面改造，让这些组件发挥实际价值，提升系统的功能完整性和用户体验。

### 1.1 整合原则

1. **功能互补**: 未引用组件应补充现有功能，而非简单替换
2. **渐进式整合**: 优先整合高价值组件，逐步完善系统
3. **向后兼容**: 保持现有功能稳定，新功能作为增强
4. **用户体验**: 整合后应提升用户体验，而非增加复杂度

### 1.2 整合策略分类

| 策略类型 | 组件数量 | 说明 |
|---------|---------|------|
| **功能增强型** | 12个 | 替换现有简单实现，提供更完整功能 |
| **新增功能型** | 8个 | 添加系统中缺失的功能模块 |
| **视图优化型** | 6个 | 提供替代视图或展示方式 |
| **示例保留型** | 5个 | 作为开发示例保留 |
| **待评估型** | 2个 | 需要进一步评估后再决定 |

## 2. 功能增强型整合（12个组件）

### 2.1 库存调拨功能增强

#### 现状分析
- **现有实现**: `StockTransferPage.vue` 使用简单的表格展示调拨记录
- **问题**: 缺少新建调拨单的对话框，用户体验不够完整

#### 整合方案

**组件**: `TransferOrderDialog.vue`

**整合步骤**:

1. **修改 `StockTransferPage.vue`**

```vue
<!-- 在 StockTransferPage.vue 中添加 -->
<template>
  <PageLayout title="库存调拨" description="管理仓库间设备调拨">
    <template #headerActions>
      <el-button type="primary" :icon="Plus" @click="handleCreate">
        新建调拨单
      </el-button>
      <!-- ... 其他按钮 -->
    </template>
    
    <!-- ... 现有表格代码 -->
    
    <!-- 新增：调拨单对话框 -->
    <TransferOrderDialog
      v-model="dialogVisible"
      :mode="dialogMode"
      :data="currentRow"
      @success="handleDialogSuccess"
    />
  </PageLayout>
</template>

<script setup>
import { ref } from 'vue';
import TransferOrderDialog from '@/components/business/dialogs/TransferOrderDialog.vue';

const dialogVisible = ref(false);
const dialogMode = ref('create');
const currentRow = ref(null);

const handleCreate = () => {
  dialogMode.value = 'create';
  currentRow.value = null;
  dialogVisible.value = true;
};

const handleEdit = (row) => {
  dialogMode.value = 'edit';
  currentRow.value = row;
  dialogVisible.value = true;
};

const handleDialogSuccess = () => {
  dialogVisible.value = false;
  loadData(); // 刷新列表
};
</script>
```

**预期效果**:
- 提供完整的调拨单创建/编辑功能
- 支持调出/调入仓库选择
- 支持设备选择和数量配置
- 提升用户操作体验

## 7. 风险评估与应对

### 7.1 技术风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 组件兼容性问题 | 功能异常 | 逐步集成，充分测试 |
| 性能下降 | 用户体验差 | 使用 VirtualList 等优化组件 |
| 代码冲突 | 合并困难 | 使用特性分支开发 |

### 7.2 业务风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 用户不适应新界面 | 操作效率下降 | 提供操作引导，保留原有入口 |
| 数据不一致 | 业务错误 | 严格测试数据流转 |
