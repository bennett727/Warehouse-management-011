## 迁移内容

### 1. 迁移目标
将历史入库数据适配新的入库流程，为已完成的入库单补充审批记录，确保数据一致性。

### 2. 迁移步骤

#### 步骤1：数据备份
- **操作**：创建设备表和入库单表的备份
- **备份表**：
  - `device_backup_20250213`
  - `stock_order_backup_20250213`
- **状态**：✅ 完成

#### 步骤2：创建审批记录
- **操作**：为历史已完成的入库单创建设备审批记录
- **记录数**：根据实际数据量动态生成
- **状态**：✅ 完成

#### 步骤3：数据一致性验证
- **检查项**：
  - 孤儿设备检查（在库但无入库记录）
  - 各状态设备数量统计
- **状态**：✅ 完成

#### 步骤4：迁移记录
- **操作**：记录迁移执行日志
- **状态**：✅ 完成

## 迁移脚本说明

### 自动迁移组件
**文件路径**：`spring_boot/src/main/java/com/backend/util/DataMigrationRunner.java`

**核心特性**：
1. **幂等性**：自动检测是否已执行，避免重复迁移
2. **事务性**：所有操作在事务中执行，失败自动回滚
3. **日志记录**：详细记录迁移过程和结果
4. **数据备份**：自动备份原始数据

### 执行流程
```
应用启动
    ↓
检测是否已迁移
    ↓
创建备份表
    ↓
创建审批记录
    ↓
验证数据一致性
    ↓
记录迁移日志
    ↓
完成
```

## 回滚方案

### 回滚条件
- 迁移执行失败
- 数据验证不通过
- 业务测试发现严重问题

### 回滚步骤

1. **停止应用**
   ```bash
   # 停止Spring Boot应用
   ```

2. **恢复数据**
   ```sql
   -- 恢复设备表
   TRUNCATE TABLE device;
   INSERT INTO device SELECT * FROM device_backup_20250213;
   
   -- 恢复入库单表
   TRUNCATE TABLE stock_order;
   INSERT INTO stock_order SELECT * FROM stock_order_backup_20250213;
   
   -- 删除迁移记录
   DELETE FROM data_migration_log WHERE migration_version = '20250213_1';
   ```

3. **清理备份表（可选）**
   ```sql
   DROP TABLE IF EXISTS device_backup_20250213;
   DROP TABLE IF EXISTS stock_order_backup_20250213;
   ```

## 注意事项

### 1. 执行时机
- 建议在业务低峰期执行
- 确保有足够的磁盘空间存储备份

### 2. 并发控制
- 迁移执行期间避免数据修改操作
- 建议在维护窗口执行

### 3. 监控要点

## 问题排查

### 常见问题

#### Q1: 迁移执行失败怎么办？
**A**: 
1. 查看应用日志定位错误
2. 检查数据库连接和权限
3. 确认表结构正确
4. 必要时执行回滚

#### Q2: 如何确认迁移已执行？
**A**: 
```sql
SELECT * FROM data_migration_log 
WHERE migration_version = '20250213_1' AND status = 'SUCCESS';
```

#### Q3: 可以重复执行迁移吗？
**A**: 不可以。组件具有幂等性，已执行的迁移会自动跳过。
