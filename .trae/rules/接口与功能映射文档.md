# 仓库管理系统 - 接口与功能映射文档

## 1. 文档概述

### 1.1 文档目的

本文档旨在明确仓库管理系统（WMS）前后端功能模块的对应关系，定义统一的API接口规范，确保前后端开发团队在功能实现和接口交互上保持一致。文档包含功能模块清单、API接口定义、数据模型、权限控制及错误处理等关键内容，作为前后端协作开发的依据和验收标准。

### 1.2 适用范围

本文档适用于仓库管理系统的前后端开发团队、测试团队和项目管理人员。

### 1.3 术语定义

| 术语 | 解释 |
|------|------|
| WMS | 仓库管理系统（Warehouse Management System） |
| API | 应用程序编程接口（Application Programming Interface） |
| RESTful | 一种软件架构风格，用于设计网络应用程序接口 |
| JWT | JSON Web Token，一种用于身份验证的令牌 |
| RBAC | 基于角色的访问控制（Role-Based Access Control） |
| CRUD | 创建（Create）、读取（Read）、更新（Update）、删除（Delete） |

## 3. API接口定义

### 3.1 通用规则

#### 3.1.1 响应格式

所有API返回统一的响应结构：

```json
{
  "success": true/false,
  "message": "操作结果描述",
  "data": { /* 返回数据 */ },
  "code": 200 /* 状态码 */
}
```

#### 3.1.2 分页响应格式

分页查询接口返回以下结构：

```json
{
  "success": true,
  "message": "查询成功",
  "data": {
    "records": [/* 数据列表 */],
    "total": 100, /* 总记录数 */
    "size": 10, /* 每页大小 */
    "current": 1, /* 当前页码 */
    "pages": 10 /* 总页数 */
  },
  "code": 200
}
```

#### 3.1.3 错误码定义

错误码采用4位数字编码，分类如下：

| 错误码范围 | 分类 | 描述 |
|------------|------|------|
| 200-299 | 成功 | 操作成功 |
| 400-499 | 客户端错误 | 客户端请求错误或参数问题 |
| 500-599 | 服务器错误 | 服务器内部错误 |

详细错误码请参考第6章 错误处理规范。

#### 3.1.4 认证方式

所有API接口（除登录接口外）均需要在请求头中携带JWT令牌：

```
Authorization: Bearer {token}
```

### 3.2 设备管理模块API

#### 3.2.1 获取设备列表

- **请求方法**：GET
- **请求路径**：/api/v1/devices
- **请求参数**：
  | 参数名 | 类型 | 必填 | 描述 |
  |--------|------|------|------|
  | page | int | 否 | 页码，默认1 |
  | size | int | 否 | 每页大小，默认10 |
  | deviceName | string | 否 | 设备名称模糊查询 |
  | deviceCode | string | 否 | 设备编码模糊查询 |
  | deviceTypeId | long | 否 | 设备类型ID |
  | status | string | 否 | 设备状态 |
  | areaId | long | 否 | 区域ID |
- **响应数据**：分页设备列表

#### 3.2.2 获取设备详情

- **请求方法**：GET
- **请求路径**：/api/v1/devices/{id}
- **请求参数**：
  | 参数名 | 类型 | 必填 | 描述 |
  |--------|------|------|------|
  | id | long | 是 | 设备ID |
- **响应数据**：设备详情

#### 3.2.3 创建设备

- **请求方法**：POST
- **请求路径**：/api/v1/devices
- **请求体**：
  ```json
  {
    "deviceName": "设备名称",
    "deviceCode": "设备编码",
    "model": "设备型号",
    "deviceTypeId": 1,
    "status": "正常",
    "areaId": 1,
    "purchaseDate": "2023-01-01",
    "warrantyPeriod": "12个月",
    "responsiblePerson": "负责人",
    "remark": "备注"
  }
  ```
- **响应数据**：创建设备信息

#### 3.2.4 更新设备

- **请求方法**：PUT
- **请求路径**：/api/v1/devices/{id}
- **请求参数**：
  | 参数名 | 类型 | 必填 | 描述 |
  |--------|------|------|------|
  | id | long | 是 | 设备ID |
- **请求体**：同创建设备
- **响应数据**：更新后设备信息

#### 3.2.5 删除设备

- **请求方法**：DELETE
- **请求路径**：/api/v1/devices/{id}
- **请求参数**：
  | 参数名 | 类型 | 必填 | 描述 |
  |--------|------|------|------|
  | id | long | 是 | 设备ID |
- **响应数据**：删除结果

#### 3.2.6 变更设备状态

- **请求方法**：PATCH
- **请求路径**：/api/v1/devices/{id}/status
- **请求参数**：
  | 参数名 | 类型 | 必填 | 描述 |
  |--------|------|------|------|
  | id | long | 是 | 设备ID |
  | status | string | 是 | 新状态 |
- **响应数据**：更新后设备信息

#### 3.2.7 批量删除设备

- **请求方法**：DELETE
- **请求路径**：/api/v1/devices/batch
- **请求体**：
  ```json
  {
    "ids": [1, 2, 3]
  }
  ```
- **响应数据**：批量删除结果

#### 3.2.8 批量更新设备状态

- **请求方法**：PATCH
- **请求路径**：/api/v1/devices/batch/status
- **请求体**：
  ```json
  {
    "ids": [1, 2, 3],
    "status": "维修中"
  }
  ```
- **响应数据**：批量更新结果

#### 3.2.9 导出设备列表

- **请求方法**：GET
- **请求路径**：/api/v1/devices/export
- **请求参数**：同获取设备列表
- **响应数据**：Excel文件流

## 5. 权限控制

### 5.1 角色定义

| 角色名称 | 角色编码 | 描述 |
|----------|----------|------|
| 系统管理员 | ADMIN | 拥有系统所有权限，负责系统配置和用户管理 |
| 仓库管理员 | WAREHOUSE_ADMIN | 负责仓库设备管理、出入库操作和维护记录管理 |
| 设备管理员 | DEVICE_ADMIN | 负责设备的日常维护和维修管理 |
| 普通用户 | USER | 只能查看设备信息和维护记录，无操作权限 |

### 5.2 权限控制实现

#### 5.2.1 后端权限控制

后端使用Spring Security框架实现基于角色的访问控制（RBAC），主要通过以下方式实现：

1. **URL级权限控制**：使用`@PreAuthorize`注解在控制器方法上进行权限控制
2. **方法级权限控制**：使用`@PreAuthorize`注解在服务层方法上进行权限控制
3. **数据级权限控制**：在数据访问层实现基于用户角色的数据过滤

#### 5.2.2 前端权限控制

前端使用Vue Router的导航守卫实现路由级权限控制，主要通过以下方式实现：

1. **路由懒加载**：根据用户权限动态加载路由
2. **导航守卫**：在路由跳转前检查用户是否有访问权限
3. **按钮级权限控制**：根据用户权限动态显示或隐藏操作按钮

## 6. 错误处理规范

### 6.1 错误码体系

错误码采用4位数字编码，分类如下：

| 错误码范围 | 分类 | 描述 |
|------------|------|------|
| 200-299 | 成功 | 操作成功 |
| 400-499 | 客户端错误 | 客户端请求错误或参数问题 |
| 500-599 | 服务器错误 | 服务器内部错误 |

### 6.2 通用错误码

| 错误码 | 描述 | 客户端处理建议 |
|-------|------|--------------|
| 200 | 成功 | 正常处理响应数据 |
| 400 | 参数错误 | 检查请求参数格式和内容是否符合要求 |
| 401 | 未授权 | 重新登录获取有效令牌 |
| 403 | 禁止访问 | 检查用户是否有足够权限执行此操作 |
| 404 | 资源不存在 | 确认请求的资源ID或路径是否正确 |
| 405 | 方法不允许 | 检查请求方法是否正确（GET/POST/PUT/DELETE等） |
| 500 | 服务器内部错误 | 联系系统管理员，记录错误日志 |
