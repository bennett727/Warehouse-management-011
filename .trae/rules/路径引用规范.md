# 路径引用规范

## 1. 概述

为了提高代码的可维护性和可读性，统一项目中的路径引用方式，特制定本规范。本规范适用于小型仓库管理系统前端项目（Vue 3 + Vite）的所有文件。

## 2. 路径别名配置

项目使用 Vite 构建工具，已配置以下路径别名：

| 别名 | 指向路径 | 示例 |
| --- | --- | --- |
| `@/` | `src/` | `@/components/Button.vue` |

配置文件位置：`config/vite.config.js`

```javascript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import path from 'path'

const pathResolve = (dir) => {
  return path.resolve(__dirname, dir)
}

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': pathResolve('src')
    }
  },
  // ...其他配置
})
```

## 3. 导入语句规范

### 3.1 JavaScript/TypeScript 模块导入

**必须使用路径别名**，避免使用相对路径：

```javascript
// ✅ 推荐
import { useUserStore } from '@/stores/user'
import { DEVICE_PATHS } from '@/config/paths'

// ❌ 不推荐
import { useUserStore } from '../../stores/user'
import { DEVICE_PATHS } from '../config/paths'
```

### 3.2 组件导入

**必须使用路径别名**：

```javascript
// ✅ 推荐
import Button from '@/components/Button.vue'
import DeviceList from '@/views/device/DeviceList.vue'

// ❌ 不推荐
import Button from '../../components/Button.vue'
import DeviceList from '../views/device/DeviceList.vue'
```

### 3.3 静态资源导入

**必须使用路径别名**：

```javascript
// ✅ 推荐
import logo from '@/assets/logo.png'
import '@/styles/index.css'

// ❌ 不推荐
import logo from '../../assets/logo.png'
import '../styles/index.css'
```

## 4. 路由配置规范

### 4.1 路由路径定义

路由路径应使用清晰的语义化命名，避免复杂的路径拼接和处理：

```javascript
// ✅ 推荐
path: 'users',
path: 'devices',

// ❌ 不推荐
path: SYSTEM_PATHS.USER_MANAGEMENT.replace(SYSTEM_PATHS.SYSTEM + '/', ''),
path: DEVICE_PATHS.DEVICE_LIST.split('/').pop(),
```

### 4.2 路由组件导入

**必须使用路由懒加载**和路径别名：

```javascript
// ✅ 推荐
component: () => import('@/views/user/UserManagement.vue')

// ❌ 不推荐
component: () => import('../views/user/UserManagement.vue')
component: UserManagement
```

## 5. 资源引用规范

### 5.1 CSS 资源引用

```css
/* ✅ 推荐 */
@import '@/styles/variables.css';

background-image: url('@/assets/images/bg.png');

/* ❌ 不推荐 */
@import '../../styles/variables.css';

background-image: url('../../assets/images/bg.png');
```

### 5.2 Vue 模板中的资源引用

```vue
<!-- ✅ 推荐 -->
<img src="@/assets/logo.png" alt="logo">

<!-- ❌ 不推荐 -->
<img src="../../assets/logo.png" alt="logo">
```

## 6. 路径常量管理

所有页面路径应在 `@/config/paths.js` 中统一管理：

```javascript
// @/config/paths.js
export const PUBLIC_PATHS = {
  LOGIN: '/login',
  NOT_FOUND: '/404'
}

export const SYSTEM_PATHS = {
  SYSTEM: '/system',
  USER_MANAGEMENT: '/system/users',
  ROLE_MANAGEMENT: '/system/roles'
}
```

使用时直接导入：

```javascript
import { PUBLIC_PATHS, SYSTEM_PATHS } from '@/config/paths'
```

## 7. 代码格式规范

### 7.1 导入顺序

导入顺序应遵循以下规则：
1. 第三方库
2. 路径常量
3. 状态管理
4. 组件
5. 工具函数

```javascript
// ✅ 推荐
import { ref, computed } from 'vue'
import { ElMessage } from 'element-plus'
import { PUBLIC_PATHS } from '@/config/paths'
import { useUserStore } from '@/stores/user'
import Button from '@/components/Button.vue'
import { formatDate } from '@/utils/format'

// ❌ 不推荐（顺序混乱）
import Button from '@/components/Button.vue'
import { PUBLIC_PATHS } from '@/config/paths'
import { ref, computed } from 'vue'
import { useUserStore } from '@/stores/user'
import { ElMessage } from 'element-plus'
import { formatDate } from '@/utils/format'
```

### 7.2 多行导入

当导入内容较多时，应使用多行格式：

```javascript
// ✅ 推荐
import {
  PUBLIC_PATHS,
  SYSTEM_PATHS,
  DEVICE_PATHS,
  REPAIR_PATHS
} from '@/config/paths'

// ❌ 不推荐（单行过长）
import { PUBLIC_PATHS, SYSTEM_PATHS, DEVICE_PATHS, REPAIR_PATHS } from '@/config/paths'
```

## 8. 检查与验证

### 8.1 构建验证

所有路径引用的正确性可通过以下命令验证：

```bash
# 开发环境构建
npm run dev

# 生产环境构建
npm run build
```

### 8.2 ESLint 检查

项目配置了 ESLint 规则，可通过以下命令检查代码格式：

```bash
npm run lint
```

## 9. 违规处理

1. 所有新编写的代码必须遵循本规范
2. 现有代码在修改时应逐步迁移至本规范
3. 代码审查时应重点检查路径引用是否符合规范
